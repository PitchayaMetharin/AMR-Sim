# Fix hospital abort loop + make exploration planning fast

## Context
Hospital run 10 (`.ros_logs/hospital_explore_20261008_10`, all fixes in) mapped 751 m², reached 9 goals, then
looped: every departure path was rejected. Two problems remain.

**1. Abort loop — cause proven.**
- **Smoother error:** `smoother_server` logged "Smoothed path leads to a collision at x: -5.674, y: -32.124" 9×.
  That pose is the robot's own parked pose (the path start).
- **Costmap at the parked pose:** the parked footprint touches one 254 cell, 0.729 m from the centre. That is
  inside the 0.735 m circumscribed disk, so goal 9 should never have passed the turn-in-place gate.
- **Gate bug:** `_turn_clearance_checker` (`src/amr_exploration/scripts/frontier_algorithm.py:~896`) builds its
  cell-offset list with gap `max(dx-1, -dx, 0)`. On the negative side it should be `-(dx+1)`, so the ring of
  cells just inside the disk on the −x/−y sides is never checked.
- **Confirmed:** an exact disk check reports `clear=False` for the cell at offset (−13, 8); the helper's offset
  list omits that cell.
- **Why tests missed it:** the root test oracle `_disk_clear` is correct, but no test put an obstacle on the
  −x/−y side.

**2. Slow "calculating path".** On the hospital map, planning takes 21–27 s per goal (grows with map area).
Profile on `.ros_logs/hospital_explore_20261008_04/capture.pkl` (500×472): selector 6.3 s.
- **Route search:** `_reachable_costmap_cells`, 3.7 s.
  - BFS 1.2 s.
  - `turn_clear` 1.1 s (0.5M calls).
  - 41 footprint masks 1.1 s.
- **Approach endpoints:** `_approach_endpoints`, 2.1 s, of which 4.2M brute-force `min()` distance terms is
  the main part.
- **Root cause of most of the route-search cost:** when the highest-priority frontier is unreachable,
  `stop_after_first` still searches the whole map.
- **User decision:** switch to **nearest reachable frontier first**.

## Step 2 — Fast planning (Haiku max), all in `frontier_algorithm.py`
Root writes and pins tests first. Golden outputs are generated by root from the **post-step-1** code, before
any optimisation.

- **2a. Nearest-first route proof.**
  - **Change:** in `_reachable_costmap_cells(..., stop_after_first=True)`, return the **first target reached
    in BFS order** (fewest grid steps, ties by existing deterministic queue order) and exit immediately.
  - **Early exit in both modes:** stop as soon as `remaining` is empty.
  - **Exhaustive case unchanged:** when nothing is reachable, the search is still exhaustive, so COMPLETE and
    blocked classification are unchanged.
  - **`costmap_frontier_candidates`:** keeps its contract; its candidate list is `[nearest reachable endpoint]`.
- **2b. Cheap turn checks.**
  - Precompute one "blocked at any of the 32 headings" union mask (OR of `heading_masks`).
  - `turn_clear` / `goal_turn_clear` return immediately for cells not set in the union mask.
  - Inline the `blocked()` / `cost()` hot calls in the BFS loop.
  - Results are exactly identical.
- **2c. Exact fast approach distances.** In `_approach_endpoints`, replace the per-sampled-cell `min()` over
  all cluster cells with a spatial bucket grid (bucket ≥ approach radius). Only adjacent buckets are scanned.
  The distance is the same Euclidean minimum, so outputs are identical.
- **Out of scope for now:** the reachability cache for patrol (plan B part 2) — patrol is opt-in and off by
  default.

**Root-written pinned tests** (new `src/amr_exploration/test/test_frontier_planning_speed.py`; fixtures in
`test/fixtures/` as zlib+base64 JSON, stdlib only):
- **Equivalence:**
  - Exhaustive `_reachable_costmap_cells` sets are identical to goldens on ~6 seeded synthetic maps (rooms,
    corridors, pockets, unknown space) and on two hospital fixtures (capture 04, run 10 costmap+map).
  - `_approach_endpoints` outputs are identical to goldens.
- **Nearest-first:**
  - Scene: a small reachable cluster near the robot plus a large reachable cluster far away. The near one must
    be chosen (old code picks the large one, so red).
  - The chosen candidate must be in the golden exhaustive reachable set, and must pass the footprint check and
    turn gate.
- **Completion unchanged:** when no frontier is reachable, candidates are `[]` and diagnostics equal the
  goldens.
- **Performance guard:** on the hospital fixture, selector wall time ≤ 2.0 s. Root measures the baseline
  first and sets the bound with a margin of at least 2×.
- **Existing suites:** amr_exploration stays 0 failures. Patrol tests stay green (patrol uses the exhaustive
  mode).
